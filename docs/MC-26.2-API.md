# Minecraft 26.2 — API signatures, verified against the jar

Everything here was read with `javap` from the Mojang-mapped jar, not from
memory. Model training data for 26.x is thin and confidently wrong, and the two
entries at the top are exactly the kind of change it gets wrong: both compiled
fine in older versions with completely different code.

```bash
javap -cp ~/.gradle/caches/fabric-loom/26.2/minecraft-common.jar <class>
```

## Chat clicks: `ClickEvent` is an interface now

It used to be a class you constructed with an action enum. In 26.2 it is an
interface with a record per action, and the URL variant takes a `URI`, not a
`String`:

```java
new ClickEvent.OpenUrl(URI.create("https://alacraft.day/en/logs/aB3xY9kM"))
new ClickEvent.RunCommand("/alalogger delete aB3xY9kM")
new ClickEvent.SuggestCommand("/alalogger share ")

Style.EMPTY
    .withColor(ChatFormatting.AQUA)
    .withUnderlined(true)
    .withClickEvent(new ClickEvent.OpenUrl(uri))
    .withHoverEvent(new HoverEvent.ShowText(Component.literal("Open in your browser")));
```

`HoverEvent` follows the same shape — `HoverEvent.ShowText(Component)`.

## Permissions: a `PermissionCheck`, not an int

```java
Commands.literal("alalogger")
    .requires(Commands.hasPermission(Commands.LEVEL_GAMEMASTERS))   // op level 2
```

Constants: `LEVEL_ALL`, `LEVEL_MODERATORS`, `LEVEL_GAMEMASTERS`, `LEVEL_ADMINS`,
`LEVEL_OWNERS` — all `net.minecraft.server.permissions.PermissionCheck`. The old
`.requires(src -> src.hasPermission(2))` form is gone.

## Command source

```java
public void sendSuccess(Supplier<Component>, boolean broadcastToAdmins)
public void sendFailure(Component)
public MinecraftServer getServer()
public ServerPlayer getPlayer()          // null on the console
public boolean isPlayer()
```

`sendSuccess` takes a **supplier**, so a message that is expensive to build is
not built when nobody will see it.

## The player's language

```java
serverPlayer.clientInformation().language()   // "ru_ru", "de_de", ...
```

This is what makes per-player translation possible without the mod being
installed client-side: the server already knows the language, so it can resolve
the text itself and send a plain literal.
